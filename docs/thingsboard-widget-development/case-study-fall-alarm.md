# 跌倒告警组件 - 最佳实践案例

> 项目类型: IoT 告警处理 Widget
> 技术栈: ThingsBoard + PostgreSQL
> 应用场景: 老人看护 / 智能家居
> 案例日期: 2026-03-21

---

## 一、项目概述

### 1.1 需求背景

开发一个跌倒检测告警系统，用于老人看护场景：
- 实时监测老人活动状态
- 检测到跌倒时立即告警
- 支持呼叫急救、通知家人
- 记录完整处理时间线

### 1.2 核心功能

| 功能模块 | 说明 |
|---------|------|
| 跌倒检测 | 传感器实时监测，自动触发告警 |
| 告警卡片 | 可视化展示告警信息 |
| 一键呼叫 | 呼叫急救服务 (120) |
| 通知家人 | 短信/电话通知紧急联系人 |
| 标记误报 | 处理完成后标记状态 |
| 时间线记录 | 完整记录从检测到结束的全过程 |

## 三、核心设计模式

### 3.1 混合存储架构

| 存储层 | 位置 | 用途 | 数据格式 |
|--------|------|------|----------|
| 实时缓存 | tb_attributes | Widget 实时显示 | JSON |
| 历史归档 | alarm_timelines | 历史查询、统计 | JSONB |
| 系统告警 | tb_alarm | ThingsBoard 告警管理 | 结构化 |

### 3.2 生命周期时间线

```
DETECTED ──▶ NOTIFIED ──▶ RESPONDED ──▶ HANDLING ──▶ RESOLVED ──▶ ARCHIVED
   │            │             │             │            │            │
 传感器      系统通知      值班确认      呼叫急救     标记误报      归档
 触发        创建告警      告警          处理          解决
```

### 3.3 RPC 通信设计

| RPC 方法 | 参数 | 功能 |
|----------|------|------|
| `callEmergency` | alarmId, location, resident | 呼叫急救服务 |
| `notifyFamily` | alarmId, message, contacts | 通知紧急联系人 |
| `markAsFalseAlarm` | alarmId, reason, operatorId | 标记为误报 |

## 四、数据库设计

### 4.1 核心表结构

```sql
-- 告警时间线主表
CREATE TABLE alarm_timelines (
    id SERIAL PRIMARY KEY,
    alarm_id VARCHAR(50) UNIQUE NOT NULL,
    tenant_id VARCHAR(50) NOT NULL,
    device_id VARCHAR(50) NOT NULL,
    resident_id VARCHAR(50),
    resident_name VARCHAR(100),
    
    -- 核心数据（JSONB 格式）
    events JSONB NOT NULL DEFAULT '[]',
    statistics JSONB DEFAULT '{}',
    outcome JSONB DEFAULT '{}',
    
    -- 关键时间戳
    detected_at TIMESTAMP NOT NULL,
    acknowledged_at TIMESTAMP,
    resolved_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 索引设计
CREATE INDEX idx_timelines_device ON alarm_timelines(device_id);
CREATE INDEX idx_timelines_resident ON alarm_timelines(resident_id);
CREATE INDEX idx_timelines_detected ON alarm_timelines(detected_at DESC);
CREATE INDEX idx_timelines_events ON alarm_timelines USING GIN (events);
```

### 4.2 实体关系

```
TB_DEVICE ||--o{ ALARM_TIMELINES : generates
TB_TENANT ||--o{ ALARM_TIMELINES : owns
TB_RESIDENT ||--o{ ALARM_TIMELINES : triggers
ALARM_TIMELINES ||--o{ TB_ATTRIBUTES : cached
```

## 六、最佳实践要点

### 6.1 架构设计原则

1. **分层设计**：感知层 → 平台层 → 应用层 → 服务层
2. **混合存储**：属性表(实时) + PostgreSQL(历史)
3. **事件驱动**：时间线模式记录完整生命周期
4. **松耦合**：Rule Chain 转发实现模块解耦

### 6.2 性能优化

- 实时响应：属性表读取 < 100ms
- 历史查询：PostgreSQL 索引优化 < 500ms
- 批量同步：定时 + 事件触发减少写操作

### 6.3 注意事项

- 避免循环转发（添加 forwarded 标记）
- 批量同步（定时 + 事件触发）
- 错误处理（try-catch + 重试）
- 数据清理（保留策略: 90天）
